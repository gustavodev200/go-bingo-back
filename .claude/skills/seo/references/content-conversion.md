# FAQ, Página de Posicionamento e Cases

Conteúdo de conversão — a parte que transforma visita em confiança e
confiança em ação. Regra central de toda esta página: **nunca inventar
informação, cliente, depoimento, métrica ou resultado.** Onde não houver
dado real, crie só a estrutura vazia pronta para receber conteúdo real
depois.

## FAQ baseada em dores reais

Não gere pergunta genérica de preenchimento. Antes de escrever, identifique
a partir do produto real:

1. Principal problema enfrentado pelo usuário.
2. Segunda maior dificuldade.
3. Principal objeção antes de comprar/usar.
4. Dúvida frequente sobre como funciona.
5. Dúvida sobre confiança, segurança, preço ou resultado.

Cada resposta:

- [ ] Objetiva, em linguagem natural (não copy inflado).
- [ ] Explica como o produto resolve o problema específico da pergunta.
- [ ] Elimina a objeção em vez de contorná-la.
- [ ] Usa termos que o público-alvo realmente busca (relevantes a SEO, sem
      forçar).
- [ ] Direciona para uma ação quando fizer sentido (link para
      funcionalidade, preço, contato).

## Página de posicionamento / prova

Estrutura: **Problema → Contexto → Solução → Diferenciais → Benefícios →
Provas → Confiança → CTA**. Não é uma lista de funcionalidades — é um
argumento.

- Problema: qual problema existe, de forma que o público-alvo se
  reconheça.
- Contexto: por que esse problema importa (custo de não resolver).
- Solução: como o produto resolve, em termos de resultado, não de feature.
- Diferenciais: por que esta solução em vez de alternativa conhecida.
- Benefícios: que transformação real o usuário obtém.
- Provas: evidência real disponível (métrica real, integração conhecida,
  case real) — se não houver prova real ainda, omita a seção ou marque
  como pendência, não invente número.
- Confiança: segurança, garantia, suporte, transparência.
- CTA: próximo passo único e claro.

## Cases com storytelling

Estrutura narrativa por case:

```text
ANTES → qual era o problema
CONTEXTO → quem era o usuário/cliente
DESAFIO → o que impedia o resultado
SOLUÇÃO → como o produto foi usado
TRANSFORMAÇÃO → o que mudou
RESULTADO → qual foi o impacto
```

- [ ] Cada case real responde: problema anterior, como fazia antes, por
      que não funcionava, como conheceu a solução, como usou, o que
      mudou, resultado obtido.
- [ ] **Sem case real disponível ainda**: crie só o template/estrutura da
      seção (título, campos vazios ou placeholder explícito de "case em
      breve"), nunca um case fictício apresentado como real.
- [ ] Nome, empresa, métrica e depoimento só entram se forem reais e
      houver permissão de uso.
