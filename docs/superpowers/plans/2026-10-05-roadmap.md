## Pontos de sincronização entre os repos

1. **Contrato** — `go-bingo-back/src/contracts/` é a fonte da verdade (schemas Zod, nomes de eventos, regras puras de bingo). `npm run contracts:sync` no back copia para `go-bingo-front/src/contracts/`. Toda mudança de contrato: editar no back → rodar sync → commit nos dois repos.
2. O front começa depois que o Task 2 do plano do back (contratos) estiver commitado.
3. O teste manual ponta a ponta do front (último task do plano 2) exige o back rodando localmente e o projeto Supabase configurado (PRD §6.2).

## Pré-requisitos externos (você)

- Projeto Supabase criado com **asymmetric JWT signing keys** ativas (o back valida tokens pela JWKS), provider **Google**, **Anonymous sign-ins**, **Manual linking** e **CAPTCHA Turnstile** habilitados; URLs `http://localhost:3000/auth/callback` (e as de preview/produção depois) na allow list de redirect.
- Docker rodando (Postgres local do back).
- Node 24 + npm (ambiente atual).
